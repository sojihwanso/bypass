# 선사록 해운 소식 자동 수집 설계 (v3.1.0)

- 날짜: 2026-11-26
- 대상: `apps/ship_info/index.html`(해운 소식 화면·홈 소식 칸), 새 Supabase Edge Function `supabase/functions/ship-news/`, 새 SQL `supabase/038_ship_news.sql`

## 왜 하는가

해운 소식은 직접 골라 넣은 40건(2026-02-16~11-24)뿐이라 새 소식이 들어오지 않는다. 사용자 요청:
- 다루는 주제를 넓힘: 조선, 항만, 해외 해운사 소식까지
- 더 많은 매체에서 받음
- 갱신은 하루 한 번이면 충분

## 목표 / 하지 않을 것 / 실패로 보는 것

- 목표: 하루 한 번 자동으로 해운·조선·항만 소식을 모아 기존 40건과 합쳐 보여 준다. 분류 필터로 좁힐 수 있다.
- 하지 않을 것: 기사 본문 저장·전재(제목, 매체, 날짜, 링크, 짧은 요약만), 영어 매체(이번에는 한국어만, 아래 '나중에'), 관리자 화면, 로그인.
- 실패로 보는 것
  - 해운과 상관없는 기사가 많이 섞임
  - 같은 기사가 매체만 바꿔 여러 번 뜸
  - 서버가 없거나 실패할 때 소식 화면이 비거나 멈춤(지금처럼 40건은 늘 보여야 함)
  - Supabase 무료 사용량을 넘김

## 접근 방식 (고른 것: A)

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A** | Supabase Edge Function + 표. 24시간 넘은 뒤 첫 요청 때 새로 수집 | 매일 배포 없음, BYPASS '미국 증시'(`supabase/functions/market`)와 같은 방식 | 처음 한 번 SQL 실행·함수 올리기를 사용자가 대시보드에서 함 |

사용자가 A를 골랐다.

## 결정된 것

### 수집처 (2026-11-26 실제로 응답 확인)
- 해운 전문지 RSS(모두 해운·물류 전문이라 그대로 받음):
  - 쉬핑뉴스넷 `https://www.shippingnewsnet.com/rss/allArticle.xml`
  - 해양한국 `https://www.monthlymaritimekorea.com/rss/allArticle.xml`
  - 한국해운신문 `https://www.maritimepress.co.kr/rss/allArticle.xml`
  - 카고뉴스 `https://www.cargonews.co.kr/rss/allArticle.xml`
- 구글 뉴스 검색 RSS(한국어, 일반 언론까지 넓게): `https://news.google.com/rss/search?q=<검색어>+when:3d&hl=ko&gl=KR&ceid=KR:ko`. 검색어(주제별):
  - 해운: `해운`, `선사 선박`, `컨테이너선 운임`, `벌크선`, `유조선 OR 탱커`, `LNG선`
  - 조선: `조선소 수주`, `선박 발주`
  - 항만: `부산항`, `항만 물동량`
  - 해외 해운사: `머스크 OR MSC OR CMA CGM`, `코스코 OR 하파그로이드 OR ONE 해운`, `에버그린 OR 양밍 OR HMM`
  - 선원: `선원 해기사`, `해양사고`
- 한 번 수집에 요청 약 20개, 각 8초 제한, 실패한 곳은 건너뛴다.

### 구글 뉴스 링크 (빌더 확인 뒤 정함, 내 판단)
- 구글 뉴스 RSS의 링크는 원문이 아니라 `news.google.com/rss/articles/…` 중계 주소다. 그대로 저장·연결한다(누르면 구글이 원문으로 넘겨 줌). 원문 주소로 풀려면 기사마다 추가 요청이 필요해 수집이 수백 번 요청으로 커지므로 하지 않는다. 그래서 전문지 기사와의 중복은 제목 키로만 잡는다.

### 고르기·분류
- 구글 뉴스 결과는 제목에 해운 관련 낱말(배, 선박, 선사, 해운, 항만, 항구, 조선, 컨테이너, 벌크, 탱커, 운임, 선원, 해기사, 해양, 항로, LNG선 등 목록)이 하나라도 있어야 받는다. 전문지는 그대로 받는다.
- 같은 기사 판정: 원문 주소가 같거나, 제목에서 괄호·특수문자·매체명을 뺀 앞 30글자가 같으면 하나만 둔다(먼저 들어온 것).
- 분류(제목+요약 낱말 규칙, 위에서부터 처음 맞는 것): 사고 → 선원과 채용 → 조선 → 항만 → 운임과 원자재 → 실적과 시황 → 정책과 제도 → 선대와 발주 → 해외 해운사(해외 선사 이름) → 기업 소식(나머지). 기존 7개에 **조선, 항만, 해외 해운사** 3개가 새로 생긴다.
- 요약: RSS description의 태그를 지우고 120자까지. 제목과 같거나 비면 빈 값.

### 저장 (Supabase)
- 표 `ship_news`: `u`(원문 주소, 기본 키), `d`(날짜 YYYY-MM-DD, 한국 시간), `c`(분류), `t`(제목, 200자), `s`(매체, 40자), `p`(요약, 120자), `k`(제목 정규화 키), `fetched_at`.
- 표 `ship_news_meta`(한 줄): `last_fetch`, `last_ok`, `last_error`.
- 45일 넘은 소식은 수집할 때 지운다(응답은 30일치라 그보다 조금 넉넉히). 회원은 표를 직접 못 읽고 함수만 쓴다(`market_cache`와 같은 권한).

### 함수 `ship-news`
- GET 하나. 로그인 필요 없음(공개 소식), 대시보드에서 'Verify JWT' 끔. CORS는 BYPASS 주소만(market과 같은 목록).
- 동작: `last_fetch`가 24시간 넘었으면 먼저 `last_fetch`를 지금으로 바꾸고(동시에 여러 번 수집하지 않게) 수집·저장한 뒤 돌려준다. 아니면 표에서 바로 돌려준다.
- 응답: `{updated:'ISO 시각', items:[{d,c,t,s,u,p}]}`. 주소에 `?since=<ISO 시각>`이 있으면 그 뒤에 새로 들어온 소식만(최대 300건), 없으면 최신 150건. (실제 수집량이 3일에 약 600건으로 예상보다 많아 구현 중 바꿈, 내 판단)
- 구글 뉴스는 검색어마다 최신 10건만 받는다. 카고뉴스는 항공 화물 기사가 섞여 해운 낱말로 거른다.

### 앱 (선사록 v3.1.0)
- `NEWS_FEED.url = 'https://itzdjdgjqcpmxdfssfel.supabase.co/functions/v1/ship-news'`.
- 받은 소식은 지금 코드(`mergeNews`)대로 기존 40건과 합치고 주소 기준 중복 제거. 직접 고른 40건과 자동 수집 소식은 목록에서 작은 `자동 수집` 표시로 구분한다.
- 브라우저 캐시는 덮어쓰지 않고 쌓는다: 이미 저장된 자동 수집 소식과 새로 받은 것을 주소 기준으로 합치고, 90일·500건까지 남긴다(약 200KB). 그래서 한 번이라도 방문한 사람은 30일 지난 소식도 '전체' 기간에서 계속 본다. (빌더 확인 뒤 정함, 내 판단)
- 브라우저는 localStorage 캐시가 6시간 안이면 서버에 묻지 않는다(`refreshMinutes` 30 → 360, 첫 화면에서도 캐시 시각을 먼저 봄).
- 분류 필터에 조선·항만·해외 해운사 추가. 소식 화면 안내 줄: "하루 한 번 자동으로 새 소식을 받습니다. 마지막 갱신 ○월 ○일 ○시."
- 함수를 아직 안 올렸거나 실패하면 지금처럼 40건 + 저장된 소식만 보이고 안내 줄로 알린다.

### 용량 (Supabase 무료 기준, 2026-11 공개 한도)
- 저장: 하루 새 소식 약 50~100건 × 약 400바이트, 45일 보관 → 2MB 안팎(DB 500MB 한도의 1% 미만).
- 함수 호출: 브라우저마다 6시간에 한 번 → 방문 1,000명/일이라도 하루 4,000회 이하(월 50만 회 한도의 약 24%). 수집(외부 요청 약 20개)은 하루 한 번.
- 내려받는 양: 응답 300건 약 100KB(gzip 약 30KB) → 하루 4,000회라도 하루 약 120MB, 월 3.6GB. 무료 전송량(월 5GB) 안이지만 여유가 크지 않으므로 응답을 **최근 30일·200건**으로 줄여 약 절반으로 둔다. 실제 사용량은 대시보드 Usage에서 확인.

### 지켜야 할 것
- 다크모드, 고지, 출처 표기 유지. 자동 수집 소식은 원문 링크로만 연결.
- 함수 코드는 외부 라이브러리 없이(market처럼 fetch만) 쓰고, RSS 해석·고르기·분류는 따로 떼어 Node로 테스트한다.
