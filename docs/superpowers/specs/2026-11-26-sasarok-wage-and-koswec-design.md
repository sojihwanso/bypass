# 선사록 선원 임금 통계와 KOSWEC 등록 업체 추가: 설계

- 날짜: 2026-11-26
- 대상: `apps/ship_info/` (선사록, 현재 v1.0.2, 단일 정적 HTML `index.html`)
- 원본 자료(공개 안 함, git 제외): `선사록 자료/`
  - `압축해제)-(최종)_261126_105218 (1).pdf` — 「2026년 한국선원통계연보」 3. 임금현황(227~297쪽, 72쪽)
  - `KOSWEC_업체_선박정보_2026-11-26.pdf` — 한국선원복지고용센터 koswec.or.kr 정보마당 › 업체조회 정리본(수집일 2026-11-26, 283쪽)

## 왜 하는가

- 학생이 **선종별 임금을 자주 찾아본다**(사용자). 선종을 고르는 단계에서 월급 수준을 같이 봐야 한다.
- 앱에 없는 회사도 찾아볼 수 있게, KOSWEC에 **선박 3척 이상 등록한 회사**만 넣는다(사용자).
- 추가되는 화면과 문구는 AI가 만든 티가 덜 나야 한다(사용자).

## 목표 / 하지 않을 것 / 실패로 보는 것

- 목표
  - 선종 화면에서 그 선종의 월평균 임금(업종별, 직책별)을 바로 본다.
  - 임금 화면 하나에서 선종 × 직책 임금을 비교한다.
  - 등록 업체 371곳(3척 이상)을 검색·필터하고, 업체마다 등록 선박 목록을 본다.
  - 이미 앱에 있는 선사 중 해당 39곳은 선사 상세에서 등록 선박을 본다.
- 하지 않을 것
  - 기존 데이터(CO, TYPES, CAP, JOB, NEWS) 내용 수정.
  - 등록 업체 332곳을 기존 선사 목록(CO)·선종 선사 표에 합치기(B안, 사용자가 고르지 않음).
  - 원양어선 최저보장임금(연보 263~265쪽, PDF 37~39쪽) 반영.
  - 대표자 이름 표시(개인 이름이라 뺀다).
  - 1~2척 회사(469곳) 넣기.
- 실패로 보는 것
  - 등록 선박 수가 선대 규모처럼 읽힘(예: HMM 선대 154척 옆에 65척이 아무 설명 없이 나옴).
  - 통계 평균이 특정 회사 급여처럼 읽힘.
  - 원본에 없는 숫자, 반올림 오류, 직책·선종 뒤바뀜.
  - 첫 화면이 눈에 띄게 느려짐.
  - 이모지, 그라데이션 카드, 큰 숫자 자랑 배너, "~를 한눈에!" 같은 문구 등 AI가 만든 티.

## 접근 방식 (고른 것: A)

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A** | 임금은 선종 화면 + 새 `#wage` 화면, 업체는 새 `#dir` 목록. 데이터는 별도 JSON을 필요할 때 불러옴 | 선대 규모와 등록 수가 섞이지 않음, 첫 화면 가벼움 | 파일이 늘고 불러오기 실패 처리가 필요 |
| B | 332곳을 CO에 합쳐 선종 표에 노출 | 한 표에서 다 봄 | 표가 몇 배로 길어지고 '선종에서 빠르게 좁히기' 흐름이 무너짐 |
| C | A와 같은 구성, 데이터 전부 index.html 안에 | 구조 단순 | index.html이 약 300KB 늘어 휴대폰 첫 화면이 느려짐 |

사용자가 A를 골랐다.

## 결정된 것

### 선종 이름 표시 (사용자)
새 데이터와 함께 앱 선종을 보여 줄 때는 **앱 선종 이름 뒤에 KOSWEC·통계의 선종 이름을 괄호로** 붙인다. 예: `벌크선 (잡화)`, `석유제품선/케미컬선 (유조·케미컬)`, `LNG선 (LNG)`. 이름이 비슷해도 일관되게 붙인다.

| 앱 선종 id | 앱 이름 | 괄호 안(KOSWEC·통계 선종) |
|---|---|---|
| lng | LNG선 | LNG |
| lpg | LPG선/가스선 | LPG |
| crude | 원유운반선 | 유조 |
| container | 컨테이너선 | 컨테이너 |
| pctc | 자동차운반선 | 자동차 |
| bulk | 벌크선 | 잡화 |
| product | 석유제품선/케미컬선 | 유조·케미컬 |
| cement | 시멘트선/연안선 | 잡화·기타 (내항) |
| heavy | 중량물선/특수선 | 기타 |

- 시멘트선/연안선은 **내항선 업종의 잡화·기타 줄만** 쓴다. 중량물선/특수선의 기타는 자료가 있는 모든 상선 업종(외항·해외취업·내항)에서 쓴다. (빌더 확인에서 나온 질문, 내가 정함)
- 같은 통계 선종을 두 앱 선종이 함께 쓰면 그 화면마다 "○○선과 함께 '잡화'로 집계됨" 같은 한 줄을 단다: 유조(원유선·제품선), 잡화(벌크선·시멘트선), 기타(시멘트선·중량물선).
- '등록 업체 보기' 링크는 묶인 선종을 모두 넘긴다. `#dir?type=`은 쉼표로 여러 값을 받는다(기존 `r=미주,유럽`과 같은 방식).
- 통계와 KOSWEC의 선종 이름이 다르므로 **이름 대응표 하나**(`TYPE_MAP`)를 두고 링크·필터·이름표가 모두 이것을 쓴다. `#dir` 필터 값과 표시는 KOSWEC 이름 그대로, 임금 화면은 통계 이름 그대로. 대응: 급유↔급유선, 냉동↔냉동냉장, 나머지 상선 선종은 같은 이름. 어선 조업형태는 서로 잇지 않는다(어선은 선종 화면에 안 나오므로 링크가 없음).
- 여러 통계 선종이 묶인 경우(유조·케미컬 등)는 합산하지 않고 통계 선종별로 따로 보여 준다.
- 통계·KOSWEC에만 있는 선종(냉동, 여객, 예인, 예선(이접안용), 급유, 유·도선, 도선선, 어선 조업형태들)은 괄호 없이 원래 이름으로 보여 준다.
- 같은 통계 선종이 여러 앱 선종에 쓰이면(유조→원유운반선·석유제품선) 그 화면에 "원유선과 제품선이 '유조'로 함께 집계됨" 한 줄을 단다.

### 임금 데이터 (`apps/ship_info/data/wage.json`)
- 출처 표기: 「2026년 한국선원통계연보」 임금현황, 단위 천 원, "월평균 임금은 업종별 총승선원의 평균값"(원주).
- 구조: 업종 6개(외항선, 내항선, 원양어선, 연근해어선, 해외취업상선, 해외취업어선) × 선종(또는 조업형태) × 직책 21줄(합계, 해기사 계, 선장~통신장, 부원 계, 갑판장~조리원) × 값 6개(승선원 수, 계, 기본임금, 시간외수당, 상여금, 기타), 표마다 척수.
- 업종·직책별 총괄 표(PDF 1·2쪽)도 넣는다.
- 원본 '-'는 null로 둔다(0이 아님). 화면에는 '자료 없음'이 아니라 '-'로 그대로 표시.
- 해외취업상선 '기타'(PDF 65쪽)는 "승선원 전원 외국인선원으로 임금자료 없음" 주석을 그대로 보여 준다.
- 화면 단위: **만 원**으로 바꿔 보여 준다(10,023천 원 → 1,002만 원, 반올림). 상세 펼침에 천 원 원값과 구성(기본·시간외·상여·기타)을 둔다.
- 표본이 적은 표는 "표본 적음" 표시: 척수 10척 미만 또는 해당 직책 승선원 10명 미만.

### KOSWEC 등록 업체 데이터 (`apps/ship_info/data/koswec.json`)
- 대상: 상세 선박 목록 기준 **3척 이상 371곳, 선박 3,248척**. (원본 요약 907곳·6,753척과 상세 목록 합계가 같다. 처음 분석에서 906곳·6,731척으로 셌던 것은 첫 업체 고려에스엠(주) 22척을 놓친 분석 스크립트 오류였다.)
- 묶음 항목 제외(사용자 승인): 회사가 아니라 지역별로 배를 묶어 둔 `개인선주(지역)` 13개, `연근해어선(지역)` 12개(합 2,526척)는 싣지 않는다. 출처 문단에 "개인선주·연근해어선 지역 묶음은 회사가 아니어서 뺐습니다." 한 줄을 둔다.
- 같은 회사가 업종별로 두 번 나온 `동원해사랑(주)`(원양어선 4척 + 연근해어선 5척, 전화·주소 같음)는 한 업체 9척으로 합친다. `태진해운(주)`(내항상선 1척 + 3척)도 같은 방식으로 4척 한 업체로 합친다.
- 어선사 제외(사용자 승인, 2026-11-26): 선박이 모두 어선(원양어선·연근해어선·해외취업어선)인 회사는 싣지 않는다(동원해사랑도 여기에 해당). 상선과 어선이 섞인 `가나마린(주)`(상선 13척 + 원양어선 1척)는 상선 회사로 남기고 14척 모두 싣는다. 결과: 371곳, 3,248척. 출처 문단에 "어선만 운용하는 회사는 뺐습니다." 한 줄을 둔다. 임금 통계의 어선 업종(원양·연근해·해외취업어선)은 그대로 보여 주되, 등록 업체로 잇는 링크는 상선 업종에만 둔다.
- 이름에 사람 이름이 붙은 `태양해운(양희정)`은 화면·id 모두 `태양해운`으로 쓴다(대표자 이름 안 싣는 원칙과 맞춤).
- 업체 필드: 이름, 업종(업체 기준), 전화, 팩스, 주소, 선박 수. **대표자 이름은 넣지 않는다.** 전화·팩스가 휴대폰 번호(010 등)면 그 번호는 뺀다(현재 1곳, 소스코리아(주)). (사용자 승인: 연락처 1안)
- 선박 필드: 선박명, 총톤수, 업종(선박 기준), 선종(용도), 선박 국적, 선주 국적.
- 출처 표기: "한국선원복지고용센터 업체조회(koswec.or.kr), 2026-11-26 수집. 센터에 선원 고용 업체로 등록된 선박 기준이며 회사의 전체 선대와 다를 수 있습니다."
- 신뢰 표시: 기존 '보도·환산·추정'과 구분되는 **'등록'** 표시를 쓴다. 임금은 **'통계'** 표시.

### 화면
1. **선종 화면 `#type-<id>`**: 선사 표 바로 아래(장단점보다 위)에 '월평균 임금' 칸.
   - 업종별(외항선 / 해외취업상선 / 내항선 중 자료 있는 것) 한 줄씩: 전체 평균과 선장·1항사·3항사·기관장·1기사·3기사.
   - 줄을 누르면 21직책 전체와 구성(기본·시간외·상여·기타)이 펼쳐짐.
   - 칸 제목에 괄호 이름: "월평균 임금 · 벌크선 (잡화)". 밑에 출처 한 줄과 `#wage` 링크.
   - 칸 끝에 "이 선종 배를 등록한 업체 보기" → `#dir?type=<통계 선종>`.
2. **임금 화면 `#wage`** (새로)
   - 업종 전환 단추 6개(기본 외항선). 표: 줄 = 선종, 열 = 전체 평균, 선장, 1항사, 3항사, 기관장, 1기사, 3기사, 척수.
   - 열 머리 누르면 그 열로 정렬. 줄 누르면 21직책 상세 펼침.
   - 업종·직책 총괄(PDF 1·2쪽)은 표 위에 짧게.
   - 주소에 상태 보존: `#wage?biz=ocean&sort=master`.
3. **등록 업체 화면 `#dir`** (새로)
   - 검색(회사명, 선박명), 필터: 업종(업체 기준), 선종(용도), 지역(주소 첫 단어: 부산, 서울 등), 정렬: 선박 많은 순(기본)·이름순.
   - 줄: 회사명, 업종, 선박 수, 많은 선종 3개, 전화. 앱에 있는 39곳은 '선사록에 있음' 표시와 선사 상세 링크.
   - 주소에 필터 보존: `#dir?biz=..&type=..&r=..&q=..&sort=..` (기존 `#type-…?` 방식과 같게).
   - 목록이 길어 처음 50곳만 그리고 '더 보기'로 늘린다.
4. **등록 업체 상세 `#firm-<이름>`** (새로): 업종, 전화, 팩스, 주소, 선종별 척수, 선박 표(선박명, 총톤수, 선종, 선박 국적, 선주 국적), 출처. 앱에 있는 회사면 선사 상세로 가는 링크.
5. **선사 상세 `#co-<이름>`** (아래 39곳만, 앱 선사 1곳 = 등록 업체 1곳, 이름으로만 잇고 관리사·자회사로 넓히지 않음):
   - 대응(앱 이름 = KOSWEC 이름): HMM=에이치엠엠(주), HMM오션서비스=에이치엠엠오션서비스(주), SM상선=에스엠상선(주), KLCSM=케이엘씨에스엠(주), K-LNG=케이엘엔지(주), 현대LNG해운=현대엘엔지해운(주), KSS해운=케이에스에스해운(주), STX오션서비스=에스티엑스오션서비스(주), KMC해운=케이엠씨해운(주). 나머지 30곳은 '(주)'만 뗀 이름이 같음: 고려에스엠, 범진상운, 남성해운, 동영해운, 동진상선, 천경해운, 범주해운, 포스에스엠, 대한해운, 대한해운엘엔지, 대한상선, 에이치라인해운, 폴라리스쉬핑, 지마린서비스, 윌헴슨쉽매니지먼트코리아, 아이엠에스코리아, 싱크로해운, 삼주에스엠, 디엘에스엠, 동진상운, 정양해운, 오션제이드쉬핑, 코리아쉽메니져스, 상지해운, 수성해운, 인터렉스메가라인, 국제해양기술, 코린스타, 동지해운, 훼어선박.
   - 1~2척이라 빠지는 앱 선사 3곳: 삼표시멘트해운(1), 동주해운(1), 대진해운(2).

### 데이터 불러오기
- 두 JSON은 해당 화면에 처음 들어갈 때 `fetch`로 불러오고 메모리에 둔다. 실패하면 칸 안에 "자료를 불러오지 못했습니다. 다시 시도" 단추.
- `vercel.json`의 `/apps/<앱>/` 하위 파일 CSP sandbox는 문서에만 걸리고 index.html은 빠져 있어 같은 출처 fetch에 문제없다(구현 때 실제 배포 주소로 확인).

### 데이터 만드는 법
- `pdfplumber`로 PDF 줄을 읽어 JSON을 만드는 스크립트를 `docs/superpowers/tools/ship_info/`에 둔다(`build_wage.py`, `build_koswec.py`). 원본 PDF 경로를 인자로 받는다. 다시 만들 수 있게 한다.
- 검증: 임금은 각 표의 '합계'가 PDF 값과 같은지, 업종 총괄 6줄이 PDF 1쪽과 같은지. KOSWEC은 업체별 'n척' 머리와 선박 줄 수가 같은지(907곳 모두 일치 확인).
- 국적 칸은 띄어쓰기가 있는 나라(마샬 제도 등)가 있어 나라 이름 목록으로 나눈다.

### 겉모습과 문구 (AI 티 줄이기)
- 기존 선사록의 표·카드 틀, 글꼴(Pretendard), 색, 다크모드를 그대로 쓴다. 새 장식 없음.
- 숫자는 표에 `tabular-nums`, 오른쪽 맞춤. 막대그래프나 큰 숫자 강조 배너는 넣지 않는다.
- 문구는 짧은 평서문. 이모지·느낌표·"한눈에", "완벽 정리", "~해보세요!" 금지. 출처와 한계를 먼저 적는다.
- 완성 뒤 `ui-ux-pro-max` 기준 점검, `/impeccable critique`, 한국어 문구는 `humanize-korean`(unslop은 영어·독일어용이라 보조로만) 점검.
